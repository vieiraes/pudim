O framework simples para Dev.

Em português. Passo a passo. Sem complicação.

Você abre o Copilot ou o Claude e diz: "cria uma tela de login". A IA começa a codar. Mas: o que exatamente deveria ser feito? Quais eram os critérios para considerar pronto? A tarefa realmente foi concluída ou só parece?

Sem uma especificação antes, o resultado vira um ciclo de retrabalho. O Pudim resolve isso: ele obriga você a pensar antes de codar — e garante que a IA trabalhe dentro do escopo que você definiu.

As 3 regras do Pudim
  1. Sem SPEC aprovada, sem código.
  2. Uma tarefa por vez. Escopo mínimo.
  3. Sem evidência, sem fechar.

Ferramenta, framework ou o meu projeto?

Isso costuma confundir quem está começando. A resposta curta: você sempre desenvolve dentro da ferramenta de IA (Claude Code ou GitHub Copilot). "Usar o Pudim" é a disciplina que essa ferramenta passa a seguir dentro do seu projeto — não é uma alternativa a ela.

É a diferença entre o carro (a ferramenta) e o piloto automático (o Pudim): você continua dirigindo o mesmo carro, só que com um modo de operar mais disciplinado.

1. A ferramenta de IA

Claude Code ou GitHub Copilot. É onde você digita os comandos /pudim-*.

2. O framework Pudim

A pasta pudim/ e os prompts em .github/ que você copia para o seu projeto — o fluxo SPEC → TASKS → BUILD → VALIDATION.

3. O seu projeto

O STATUS.md, o CONST.md e os spec packs em pudim/specs/TASK-XYZ/ que o Pudim cria dentro do seu projeto — são seus, não vêm prontos.

Regra prática ao instalar: arquivos em pudim/templates/ e prompts em .github/ são genéricos e copiáveis. STATUS.md, CONST.md e qualquer pudim/specs/TASK-XYZ/ que você já tenha visto em exemplos não devem ser copiados — cada projeto cria os seus.

Pré-requisitos

  • Um repositório Git com o seu projeto.
  • GitHub Copilot (VS Code) ou Claude Code.
  • Node.js (usado pelo wizard de setup e por este portal).
  • Cerca de 5 minutos.

Instalação

  1. 1. Instale o Claude Code

    Siga o guia oficial: docs.anthropic.com/claude-code.

  2. 2. Copie os arquivos do Pudim para o seu projeto

    Copie a pasta pudim/ inteira para dentro do seu projeto. Depois crie os seus próprios arquivos a partir dos templates:

    cp pudim/templates/AGENTS.md AGENTS.md
cp pudim/templates/CLAUDE.md CLAUDE.md
cp pudim/templates/STATUS.md STATUS.md

    Não copie o AGENTS.md, CLAUDE.md e STATUS.md de um projeto de exemplo — eles são específicos daquele projeto.

  3. 3. Rode o wizard de setup

    chmod +x pudim/setup.sh
./pudim/setup.sh

    Ele verifica Git, Node, arquivos do Pudim e .gitignore, e mostra o que está faltando.

  4. 4. Teste

    No terminal, dentro do projeto:

    claude

    Quando a sessão abrir, digite:

    Leia o CLAUDE.md e me ajuda com o framework Pudim.

  1. 1. Instale as extensões

    No VS Code, Ctrl+Shift+X e instale GitHub Copilot e GitHub Copilot Chat.

  2. 2. Copie os arquivos do Pudim

    Copie pudim/ e .github/ (skills, prompts, agents) para o seu projeto. Depois:

    cp pudim/templates/AGENTS.md AGENTS.md
cp pudim/templates/STATUS.md STATUS.md

  3. 3. Abra o Copilot Chat

    Ícone de chat na barra lateral (Ctrl+Alt+I) e digite:

    /pudim-iniciar

    Se aparecer a sugestão do Pudim, funcionou.

O fluxo do Pudim

Toda tarefa passa pelas mesmas etapas, sem pular:

CONSTuma vez, no início
→
SPECo que vai ser feito
→
TASKSquebra em subtarefas
→
BUILDconstrói o código
→
VALIDATIONconfirma com evidência
Gates que bloqueiam o fluxo
  • /pudim-tarefa-fechar não fecha se o SPEC.md não estiver com Status: Approved.
  • /pudim-tarefa-fechar não fecha sem evidência real em cada critério de aceite do VALIDATION.md.

Comandos

/pudim-const comece aqui

Cria o CONST.md — a constituição do projeto (regras inegociáveis). Faz 6 perguntas socráticas, apresenta um Plano de Ação que você aceita ou contesta e só então grava o arquivo. Depois, é consultado pelos comandos de tarefa. Rode uma vez, antes de qualquer tarefa.

/pudim-iniciar

Começa uma tarefa do zero: pergunta objetivo, cria o card no STATUS.md e gera SPEC + TASKS + VALIDATION.

/pudim-tarefa-registrar

Registra só o card no STATUS.md, sem detalhar a especificação ainda.

/pudim-tarefa-criar TASK-XYZ

Gera o pacote completo da tarefa: SPEC.md, TASKS.md e VALIDATION.md em pudim/specs/TASK-XYZ/.

/pudim-tarefa-validar TASK-XYZ

Revisa a SPEC e, se estiver completa, marca Status: Approved — libera a fase de execução (não fecha a task).

/pudim-tarefa-fechar TASK-XYZ

Verifica SPEC aprovada, revisa critérios de aceite com evidência e fecha a task no STATUS.md se tudo passou.

/pudim-status

Mostra o board completo + o contexto da task prioritária. Aceita TASK-XYZ (task específica) ou CONTEXTO (só o resumo). Sempre read-only.

Executar scripts

Roda os scripts não-interativos de verdade, com a saída aparecendo abaixo em tempo real. setup.sh é interativo e por isso não tem botão aqui — use a versão "copiar comando" da seção de instalação.

Sua primeira tarefa

Exemplo completo, do zero até o fechamento (adaptado da Cartilha):

  1. 1. Crie a tarefa

    /pudim-tarefa-registrar

    Responda com o nome, ex.: "Criar página inicial do site". O board fica:

    - [ ] TASK-001 | Criar página inicial do site | Depende de: -

  2. 2. Abra e aprove a especificação

    /pudim-tarefa-criar TASK-001

    Preencha objetivo, escopo (dentro/fora) e critérios de aceite verificáveis. Depois:

    /pudim-tarefa-validar TASK-001

  3. 3. Implemente subtarefa por subtarefa

    Siga a ordem de dependências do TASKS.md. Marque [x] conforme for concluindo. Rode /pudim-status a qualquer momento para conferir o andamento.

  4. 4. Feche com evidência

    /pudim-tarefa-fechar TASK-001

    A IA verifica cada critério de aceite e pede evidência real antes de marcar [x] no STATUS.md.

Erros comuns / FAQ

"Vou codar primeiro e preencher a spec depois"

A IA não vai respeitar o escopo porque ele não estava definido. SPEC sempre primeiro — leva 5 minutos e evita horas de retrabalho.

"Vou fazer 3 tarefas ao mesmo tempo"

Você perde o fio e fica difícil saber o que está pronto de verdade. Uma tarefa por vez, feche antes de abrir a próxima.

"Critério de aceite: deve funcionar corretamente"

Isso não é verificável. Seja específico: "o formulário exibe mensagem de erro quando o email é inválido".

"Já acabei, vou só marcar como concluído"

Sem evidência, ninguém sabe se realmente acabou. Use /pudim-tarefa-fechar TASK-XYZ — a IA confere os critérios com você.

O comando /pudim-iniciar não aparece no Copilot

Possíveis causas: a pasta .github/prompts/ não foi copiada, o Copilot Chat não está instalado, ou o arquivo pudim-iniciar.prompt.md está com nome errado. Veja o checklist completo no pudim/INSTALL.md.
